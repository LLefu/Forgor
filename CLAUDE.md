# Forgor: notes for Claude

Tauri 2 desktop app (Windows + macOS), React 19 + TypeScript + Vite, Tailwind v4. See README for features and architecture.

## Commands
- `npm test`: Vitest (unit + data-layer integration against sql.js). `npm run e2e`: Playwright against the browser build (port 1430); it first builds a project from the plugin template (`scripts/plugin-template.mjs`).
- `npm run typecheck`, `npm run lint`, `npm run build`.
- `npm run tauri dev` / `npm run tauri build`: needs cargo on PATH (`/c/Users/tommy/.cargo/bin` in Git Bash on Windows, `~/.cargo/bin` on macOS via `. ~/.cargo/env`).
- `npm run tauri dev` merges `src-tauri/tauri.dev.conf.json` (via `scripts/tauri.mjs`): identifier `com.llefu.forgor.dev`, so dev has its own database/settings, runs next to an installed Forgor, and starts on `dev-vault/` in the repo (gitignored; `__DEV_VAULT__` in vite.config.ts, only set by `vite serve`).

## Gotchas
- The folder name contains `&`, which breaks Windows `.cmd` shims (`npx`, `node_modules/.bin`). npm scripts call `node node_modules/<pkg>/<entry>` directly; do the same for new tools.
- Full-text search uses **FTS4**, not FTS5 (sql.js has no FTS5).
- `src/platform` holds the only code that may touch Tauri APIs. Import `isTauri` from `platform/env.ts` and load Tauri modules dynamically so the browser build works.
- The global shortcut is registered in Rust (`set_hotkey` command in `src-tauri/src/lib.rs`), not JS, so it survives webview reloads.
- Inline todos: `- [ ] text ^t-<id>` in markdown. **Only the editor assigns markers** (`assignMarkersInView`, after a typing pause, then it calls onChange itself because Milkdown does not report non-history transactions). `saveNote` only syncs lines that already have a marker; assigning there too raced the editor and duplicated todos. Pass `{ assignIds: true }` only when there is no editor (demo seed).
- NoteView compares saved vs. on-disk bodies with `sameContent` (ignores leading blank lines); a strict compare reloaded the editor mid-typing.
- Milkdown serializes empty paragraphs as `<br />`; `lib/markdown.ts#cleanMarkdown` strips them before saving.
- Browser mode (`npm run dev`) seeds demo data; `?empty` starts blank. `window.__wn` exposes `{ vault, sql }` there for tests.
- Drag & drop: react-arborist is given `dndRootElement` (the explorer box). Its default root is the window, where react-dnd preventDefault()s every drop and silently broke Milkdown block dragging. Tauri windows set `dragDropEnabled: false` (Windows otherwise swallows HTML5 drags).
- Tauri fs scope: `plugins.fs.requireLiteralLeadingDot` is `false` in tauri.conf.json. It defaults to true on macOS/Linux, where `**` then does not match dot-folders like `.trash` (trash failed on macOS only). That setting does not reach folders granted at runtime (the fs plugin builds that scope without it), so `access.rs` grants `.trash` / `.meetings` by name. `src/lib/config.test.ts` guards this, `dragDropEnabled` and the permissions below.
- What the webview may touch (and so every plugin, which runs in it): `src-tauri/src/access.rs`. Files: only `$APPDATA/plugins` (capabilities) and the notes folder, granted at runtime by `vault_open`, which only accepts a folder picked in Rust's own dialog (`vault_pick`), the default `Documents/Forgor`, dev-vault/ in debug builds, or (once, when `trusted-folders.json` doesn't exist yet) the folder that was already open. The list is in app data, which the webview can't write: never add `fs:default` back (its app-data scope is global, so every write command could reach app data). Dot-folders other than the app's own (`.git`, `.obsidian`…) are denied. Opening files goes through `open_path` (notes folder only, no programs/scripts, folders without an extension); `opener:allow-open-path` is gone. A refused stored folder sends the app back to folder setup (`untrusted-folder` in boot.ts). The asset protocol scope is empty in the config and granted with the notes folder. Anything that writes outside those (Create plugin project: `plugin_project_create`) runs in Rust with Rust's own dialog: a folder granted to the webview at runtime skips dot-files on macOS, so `.gitignore` failed.
- Database: `forgor.db` is preloaded (`plugins.sql.preload`) and the JS uses `Database.get`; `sql:allow-load` is not granted (it accepts absolute paths, so any SQLite file on disk). SQLite is built with `SQLITE_MAX_ATTACHED=0` (`src-tauri/.cargo/config.toml`), which blocks `ATTACH` and `VACUUM INTO`: never use them.
- CSP (`app.security.csp`): no inline or remote scripts; connections over https/wss and to localhost (for plugins using local services); `'unsafe-eval'` is for community plugins (`new Function`); style-src keeps `'unsafe-inline'` (React/Milkdown inline styles) with `dangerousDisableAssetCspModification: ["style-src"]` so Tauri's hashes don't switch it off. It only applies to built apps (dev loads the Vite server directly), so check a change with `tauri build --debug --no-bundle --config src-tauri/tauri.dev.conf.json` and run `target/debug/forgor`.
- Unhandled promise rejections show an error toast (`components/Toasts.tsx`, `showError()`); failures must never be silent.
- No native `<input type=date|time>`: they behave differently on macOS (no outside-click close, broken time picker). Use `DatePicker` / `TimePicker` from `components/DateTimePickers.tsx`.
- Folder colors: `folders.color` (schema v3); `lib/folderColors.ts#effectiveFolderColor` inherits from ancestors. Show folders with `FolderLabel` / `FolderSelect` (`features/folder/folderColors.tsx`) so the color appears everywhere. Custom controls inside Radix menus must be menu items (`ContextMenuItemRaw asChild`), otherwise the menu never closes and blocks the page.
- Keyboard shortcuts: all in one registry, `app/shortcuts.ts` (`APP_SHORTCUTS`: id, group, default `keys`, `run`; `FIXED_SHORTCUTS` are only listed: zoom, ⌘1–9, Esc) plus plugins' `shortcuts` (id `<plugin>:<id>`, under the plugin's name, defaults that clash are dropped: `collectShortcuts`). One window keydown listener (`features/shortcuts/all.ts#useShortcuts`) skips events already `defaultPrevented` (the editor's ⌘B…) and, inside a dialog, everything but ⌘/. User changes are `settings.shortcuts` (id → combos, [] = off). Combos: `lib/keys.ts` ("Mod+Shift+A"; Mod = ⌘/Ctrl, Ctrl = the Control key also on macOS; letters/punctuation read from `code` when Shift/Option change `key`). Show keys with `useShortcutLabel(id)`, never hard-coded. The global quick-menu shortcut stays `settings.hotkey` in Tauri's format (`toGlobalCombo`/`fromGlobalCombo`). In the browser build, Chrome keeps ⌘N/⌘W/⌘T for itself.
- Settings has tabs (`settingsTab` in the UI store; `openSettings(tab)`): general (updates, notes folder, trash, storage), appearance, todos, notifications, models, shortcuts.
- Never use window.confirm/alert/prompt (unsupported in the macOS webview; lint forbids them). Use `confirmDialog()` from `components/ConfirmDialog.tsx`.
- Explorer: the tree is sized to its rows; the space below and the "Notes" header are native drop zones (`features/explorer/move.ts`) that move items to the top level.
- Checklists were merged into subtasks (schema v2 migrates old rows).
- Inbox was removed (1.2): todos without a folder show on the Todos page ("No folder" group) and as a line on Today; old Inbox tabs become Todos (`migrateView`). The sidebar's Today has no count.
- Archive was removed (1.2): `trashCompleted` (boot.ts, hourly) moves top-level todos completed `settings.archiveAfterDays` ago to the Trash with their subtasks (`deleteTodo`); the setting keeps its old name. Restoring sets `todos.restored_at`, which restarts that clock (`shouldTrash`). Schema v10 moved archived todos to the Trash; `archived_at` is unused. No confirmation on completing: nothing is lost (untick, or restore from the Trash).
- Only the main window runs migrations; the popup calls `waitForSchema` (both migrating at once caused "duplicate column name").
- Tabs live in the UI store (`app/store.ts`, persisted in localStorage): notes get a tab each, pages share one; `setView` reuses an existing tab. Folders are not a view: `openFolder()` shows `FolderPanel` on the right. The todo and folder panels are exclusive (`openTodo` clears the folder and vice versa). All tabs can be closed (`view` is null → `NothingOpen`). Use `noteLinkProps()` (`app/noteLink.ts`) for anything that opens a note, so middle-click works.
- "@" links are markdown links with id URLs: `[Title](forgor://note|embed|todo|folder/<id>)` (`lib/mentions.ts`). Renames rewrite the link text in all notes (`renameMentionsEverywhere`, `renameNote`); backlinks store them as `id:<noteId>`. Milkdown strips unknown schemes from the DOM href, so the editor reads the mark attrs (`features/editor/linkPlugins.ts`), not `a.href`.
- `scripts/patch-crepe.mjs` (postinstall) patches Milkdown's built files: slash-menu `keywords` (so `/h1` works) and image blocks without a title (caption null crashed the note). It fails loudly if a target is gone. After changing it, delete `node_modules/.vite` (Vite caches the pre-bundled copy).
- `[[wiki links]]` were removed on purpose (not standard markdown); "@" links replace them.
- Popovers inside a `DialogContent` portal into the dialog (`PortalContainerContext`): Radix Dialog blocks wheel events outside itself.
- The main window has native decorations: no `data-tauri-drag-region` (it needs a permission and errors on click).
- Video/audio: a `[name.mp4](_attachments/… "width=480")` link alone in its paragraph gets our React player (`MediaPlayer.tsx`, mounted by `mediaWidget.tsx`); the width lives in the link title. Attachments trash as kind `file`.
- Images resize from the corner via `features/editor/imageResize.ts`, which intercepts Crepe's handle and writes the same `ratio` attr Crepe uses.
- Crepe's reset CSS (`.milkdown *`, `.milkdown button`) is unlayered and beats Tailwind utilities inside the editor; React widgets need the `revert-layer` rule in `editor.css`.
- Folder icons: `folders.icon` (schema v8), an uploaded image scaled to a 128px PNG data URL (`lib/folderIcon.ts`), not inherited. Draw folders with `FolderGlyph` (`features/folder/folderColors.tsx`) so the icon shows everywhere.
- Colors: presets or custom `#rrggbb` (`settings.customColors`); every picker uses `SwatchGrid` from `components/ColorPicker.tsx`.
- react-arborist `tree.get()` only finds visible rows; call `openParents(id)` first (reveal, rename).
- react-arborist rows get `min-width: max-content`; the explorer overrides it (`rowClassName="!min-w-0"`) or long names add scrollbars. The tree height is counted from `tree.isOpen` (`countVisibleRows`), since `visibleNodes` lags until the tree re-renders.

## Plugins
- Meeting recordings, Writing tools and Jira are built-in plugins in `src/plugins/<id>/` (`index.tsx` is the plugin: manifest fields + contribution points, see `plugins/types.ts`). The app shows contributions only through `plugins/registry.tsx` / `plugins/views.tsx` and only for enabled plugins: sidebar items, pages (`{ kind: "plugin", plugin, page, param }`), right-hand panels (`openPluginPanel`, exclusive with the todo/folder/plugin-info panels), a folder-panel section, Today page cards/lists (`today`: `TodayCard`/`TodayList` from `features/today/TodayCard.tsx`), note top-bar parts, the editor's writer (`useWriter`), dialogs (`hosts`), `start` (main window, while enabled), quick-menu items (`useQuickMenu`, called as a hook also while disabled), `remoteQueries`, `disableBlocked`. Core files must not import from a plugin folder (plugins import `plugins/host.ts`, never the registry: it imports them).
- Each built-in plugin has its own `version` (in its `index.tsx`), separate from the app's: raise it when the plugin changes in a release (new features: minor, fixes: patch). Jira 1.1.0 = sidebar count + notifications; Bitbucket started at 1.0.0 in app 1.1.0.
- On/off is `settings.plugins` (id → bool). Up to 0.5.1 it was `meetingsEnabled` / `writingEnabled` / `jiraEnabled`: `loadSettings` fills `plugins` from them when it has never been saved, and `setPluginEnabled` keeps writing them (`LEGACY_FLAGS`) so going back to 0.5.1 keeps the choice. Tabs of the old `jira` / `jira-folder` / `meetings` pages are rewritten on load (`migrateView` in store.ts).
- Disabling never deletes data: tables (`meetings`, `voice_samples`), `folders.jira_board`, the Jira token and the `.meetings/` notes stay, and the schema migrations stay in `data/schema.ts`. A disabled plugin's page shows a notice (`PluginPageView`). Plugin settings live in their panel (Plugins page → card), stacked with `Setting` (`plugins/ui.tsx`); Settings keeps only app-wide things and AI models.
- A community plugin that causes trouble is switched off at once and labelled (`settings.pluginFaults`: id → message/where/at, cleared when the user switches it on): `registry.tsx` `setFaultHandler`, reached through `host.ts#reportPluginFault` from (a) `PluginBoundary` (takes the plugin's `id`; every place that renders plugin code passes it, with a `fallback` where the host component must stay), (b) `plugins/listeners.ts` (window `error`: attributed by the stack, because community code is loaded with `//# sourceURL=forgor-plugin://<id>/main.js`, see `faults.ts#pluginIdFromStack`; unhandled rejections are a toast first, `REJECTION_LIMIT` in a minute switch it off), (c) `PluginMount` (start/stop), (d) `app/AppBoundary.tsx` around the whole app (finds the plugin by stack, retries the render once it's off; else a crash screen with "Reload without community plugins"). Built-in plugins are never switched off, their errors are only shown. The flag flips in the same breath as the fault record (state before saves), so a boundary that retries finds it off; clear the old label before enabling, never after. A faulted-and-off plugin is not evaluated at load (`deferred`: only its manifest; `setPluginEnabled(on)` loads it again via `reloadPlugins`), so a plugin whose top-level code hangs or crashes can't do it twice. `useWriter` and `useQuickMenu` run in a component of their own per plugin (`WriterProbes` in `PluginRuntime`, `QuickMenuProbes` in the popup, memoised, results in stores), never inside the editor or popup. `plugins/validate.ts#sanitizeDefinition` drops wrongly shaped parts at load (`Plugin.warnings`, on the card). Icons the app draws go through `SafeIcon`, the tab label through a boundary with the plugin's name as fallback. Start-up safe mode: `app/startup.ts` counts unhealthy starts (reset after 10 s or on `pagehide`); after `SAFE_MODE_AFTER` in a row `loadCommunityPlugins({ safeMode })` switches every community plugin off and labels it. A plugin made for a newer Forgor (`minAppVersion`) loads with a warning (`plugins/compat.ts`); installing one asks first (`confirmMadeForNewerApp`, `confirmUnverifiedInstall`). `initSettings` runs before the plugins load (App, Popup) and must not run again after (it would wipe the flags the loader wrote). Tests: `e2e/plugin-faults.spec.ts` (misbehaving plugins on purpose), `plugins/faults.test.ts`, `validate.test.ts`. React retries a failed render once by itself, so a one-off error never reaches a boundary: test with an error that lasts.
- Community plugins (`plugins/community.tsx`, files via `platform/plugins.ts`): a folder with `manifest.json` + `main.js` (CommonJS, run with `new Function`; `require` only gives the app's `react`, `react/jsx-runtime`, `react-dom`) + optional `styles.css` (injected while enabled) and icon. Installed ones live in `<app data>/plugins/<id>/` (the browser build keeps them in memory). Plugins are developed as their own projects (Create plugin project), not in this repo. The factory gets `api` (`plugins/api.ts`: app store/navigation/events, data layer, `storage` in the settings table as `plugin:<id>:<key>`, UI components). Changing the list bumps `usePluginsVersion` and App/Popup remount (so hook-calling contributions like `useWriter` keep a fixed order); the startup load runs once (`loadCommunityPluginsOnce`, StrictMode ran it twice and remounted mid-use). Contributions are wrapped in `PluginBoundary`. Authoring guide: `packages/plugin-api/README.md`.
- Plugin API versioning: the plugin API has the app's version (`npm run release` also sets `packages/plugin-api/package.json`), so `minAppVersion` is both. Additions in any release (a plugin using one raises its `minAppVersion`; an older app ignores unknown contribution points silently; a plugin whose `minAppVersion` is newer than the app is not refused: it loads with a warning); breaking removals/changes only in a major release, announced in the CHANGELOG a release earlier. Up to and including 1.2 nobody had published a plugin, so 1.2 removed API freely (`{ kind: "inbox" | "archive" }`, `archivedAt`); from the first published plugin on the rule applies. Documented in `packages/plugin-api/README.md` ("Versions") and the template's AGENTS.md.
- Public plugin API: `packages/plugin-api/index.d.ts` is self-contained (only React types) and is the contract for outside projects; `src/plugins/publicApi.check.ts` fails typecheck when `createPluginApi`/`PluginDefinition` stop matching it. "Create plugin project" (`features/plugins/CreateProjectDialog.tsx`) writes the template (`features/plugins/template/files/*.tpl` via `project.ts`, which has no imports so `scripts/plugin-template.mjs` can run it in Node to build a project into `.plugin-template-check/`; e2e installs that zip). The template's `AGENTS.md` is the full guide for AI/authors: keep it in step with the API (it has a recipe for a web-service plugin with a sidebar count and notifications; the e2e test "a community plugin's query runs on the app's client" does the same by hand). Plugins get the app's TanStack client through `api.app.useQuery` / `queryClient.fetchQuery` (typed `QueryOptions` in index.d.ts); without them `remoteQueries` was useless to community plugins. Its AGENTS.md also lists what the page allows (CSP, files): update it when the CSP or permissions change. Its `package.json` takes the app's own tool versions; a project outside the repo needs `@types/node` (inside the repo it resolved the app's copy, which hid that).
- Plugin icons: an `icon.svg` is drawn as a CSS mask filled with the current text color (`PluginFileIcon` in `plugins/ui.tsx`; store cards too), so any single-color line icon follows light/dark like the app's Lucide icons. The template's `src/icon.tsx` does the same in the plugin, so `icon.svg` is the one source. Its AGENTS.md has an Icon section (Lucide style: 24 grid, stroke 2, round caps, 2px padding) and a Style guide.
- Store keep-alive: `.github/workflows/store-keepalive.yml` reads the store every 3 days (free Supabase projects pause after a week idle).
- Plugin CSS: `packages/plugin-api/theme.css` holds the `@theme` tokens (the app imports it too); the app's Tailwind doesn't see plugin code (and skips the template's files, `@source not`), so a plugin must ship its own utilities.
- Plugin store: Supabase project "Forgor" (`ltqtoxulavqwhsxywxej`, free plan, personal account; not the work Vercel). Schema in `supabase/migrations/` (tables `plugins`, `plugin_versions`, `plugin_keys`, `plugin_reports`, `rate_limits`, view `store_plugins`, bucket `plugins`), edge functions in `supabase/functions/` (`plugin-publish`, `plugin-install`, `plugin-report`, shared `_shared/store.ts`; `verify_jwt = false`, they check requests themselves). The app reads the list/zips with the publishable key (`platform/store.ts`; the browser build uses `fakeStore`). Publishing: the first upload of an id returns a publish key, kept in the keychain (`secrets.rs`, `platform/secrets.ts`, name `store:<id>`); new versions need it and a higher version. No accounts; uploads are live right away. Downloads are checked against the listed sha256. Removing a plugin (`removed_at` in SQL) turns it off wherever it's installed (`applyRemovals` in `plugins/store.ts`). Installing an unverified store plugin or any zip asks first (`confirmUnverifiedInstall` in `plugins/community.tsx`); verified ones and updates don't. Updates are matched by id only (an id taken over by someone else, or a zip-installed plugin, gets offered the store's version): tying installs to a store owner id was considered and left for later. Moderation SQL is at the top of the migration. The Supabase connector here can read and deploy functions but not change data (migrations/SQL writes come back "declined"): schema changes are run in the dashboard's SQL editor.
- `openFolder(id)` emits the app event `folder-open` (`app/events.ts`), for plugins that react to folder clicks (`api.app.on`).
- `requires` (other plugins) is kept consistent by `setPluginEnabled`: on enables what it needs, off disables what needs it (the UI asks first, `features/plugins/toggle.ts`). `models` lists the AI models with `optional` and what they're `for`.

## Notifications
- Shared system in `app/notifications.ts`, for anything (plugins first; community plugins via `api.notifications`). A source registers a check with `pollForNotifications` (every 5 min, first after 15 s; plugins call it in `start`, so main window only, also while hidden in the tray) and passes what it sees to `notifyNew(source, kind, items)`: it notifies about ids not seen before, remembers them in plugin storage (`plugin:<source>:notifications.seen.<kind>`, newest 1000), the first call for a kind only takes stock (`baseline: false` when the caller already filtered on "new since"), >3 at once become one summary. A failing check only warns in the console (the pages show those errors).
- On/off: `settings.notificationsEnabled` (Settings → Notifications, with a test button) and `settings.notificationsMuted` ("plugin:kind"); plugins declare their kinds in `notifications` and `PluginInfoPanel` shows a switch each (plus the kind's `settings` component under it while on, e.g. Jira's "all comments / only mentions", `plugin:jira:notifications.comments`). Desktop: `platform/notifications.ts` → tauri-plugin-notification (JS pinned to ~2.4 to match the Rust crate; capability `notification:default`). Clicks aren't reported on desktop. On macOS the plugin sends **debug builds'** notifications as Terminal (`tauri::is_dev()` → `com.apple.Terminal`), so `tauri dev` and `tauri build --debug` show none unless Terminal may notify; check them with a release build (`tauri build --bundles app --config src-tauri/tauri.dev.conf.json`). macOS also shows no banner for the app in front (only Notification Center): then `show()` adds an in-app notice (`showNotice`, Toasts.tsx; `hiddenWhileInFront` is macOS-only), and Settings' test notification waits 5 s so you can switch away. Sound: Forgor's own (`settings.notificationSound`), synthesized and played on the default output by Rust (`src-tauri/src/sound.rs`, cpal; `play_sound`), not the system's (a named macOS sound stayed silent); a burst plays it once (at most every 3 s). `@tauri-apps/api` is pinned to ~2.11 too: the notification package pulled in 2.12, and `tauri build` refuses a Rust/JS minor mismatch. The browser build keeps them in a list; e2e uses `__wn.notifications.{sent,check}` and `__wn.fakeJira` / `fakeBitbucket` to make things happen.
- History: every notification that passes the on/off checks is also recorded (`record` in app/notifications.ts; each item of a summary separately), newest 100, as JSON in the settings table under `notification_history` (loadSettings skips unknown keys), shown by the bell (`features/notifications/NotificationsMenu.tsx`, next to Settings; opening the menu marks all read). An item's `open` (`{ page, pageParam, panel, panelParam }`, of its source plugin) is what a click opens (`openNotification`).
- Jira (`plugins/jira/notify.ts`): `assigned` (new keys in my open tickets) and `comment` (others' comments created after the last check on tickets updated since, max 20 tickets per check). Bitbucket (`plugins/bitbucket/notify.ts`): `review` (review requests in linked repos). They fetch the lists' own queries (`myIssuesQuery`, `repoPullRequestsQuery`) through `queryClient.fetchQuery`, so the cache is shared.

## AI models
- Shared by every feature (meetings, writing tools, later plugins), not owned by one. Rust `src-tauri/src/models/`: `mod.rs` (registry `MODELS` with ids `speech` / `speakers` / `language`, pinned HF revisions, sha256-checked downloads to `<app data>/models/<id>`, commands `models_*`; `ready_dir` / `model_path` give a feature its model or an error saying what to download), `llm.rs` (the one loaded language model: `load`/`shared`, `chat`, `generate`, `unload`). `src-tauri/src/language.rs`: nl/en detection from function words. JS: `platform/models.ts` (Tauri + browser fake), `app/models.ts` (store, `useModelReady`, download queue), `features/models/ModelsSettings.tsx` (Settings → AI models is the only place to delete; features show `RequiredModels`). Features must not download, delete or locate model files themselves.
- The language model's id was `summary` up to 0.5.1; `migrate_folders` renames `<app data>/models/summary` at startup.

## Meeting recordings
- Rust in `src-tauri/src/meetings/`: `recorder.rs` (cpal: mic + system loopback, 16 kHz WAVs flushed every 5 s), `process.rs` (Silero VAD + Parakeet v3 via sherpa-onnx, echo filter, `detect_language`, summary prompts on `models::llm`), `mod.rs` (commands, tray/dock indicators). Recordings live in `<app data>/recordings/<id>/` until the note is written.
- llama.cpp's built-in chat templates don't know Gemma 4: `models::llm::chat()` writes its format by hand. Changing the language model means changing that too.
- JS side: `platform/meetings.ts` (Tauri + an in-memory fake for the browser build/e2e), `data/meetings.ts` (table `meetings`, schema v4), `plugins/meetings/state.ts` (runtime store, processing queue, startup recovery; the plugin's `start`), `lib/meetingNote.ts` (note markdown).
- Unassigned recordings are notes in `.meetings/` (`MEETINGS_DIR`): the one dot-folder whose `.md` files are indexed (`isIndexedPath`), with no folder row (`ensureFolderRow` skips ignored paths) and hidden from the explorer (`isMeetingsPath` in `buildTree`). `TauriVault.list` must keep walking into it.
- Needs CMake to build (llama.cpp). sherpa-onnx downloads its static libs at build time.
- macOS minimum is 12.0 (`bundle.macOS.minimumSystemVersion`): `tauri build` passes it as MACOSX_DEPLOYMENT_TARGET, and llama.cpp fails below 10.15 ("'path' is unavailable"). A plain `cargo build` doesn't set it, so only release builds showed the error.
- Windows: also needs libclang (LLVM; `LIBCLANG_PATH=C:\Program Files\LLVM\bin`, bindgen in llama-cpp-sys-2). sherpa-onnx's Windows libs use the static CRT (/MT), so `src-tauri/.cargo/config.toml` builds everything with it (`+crt-static`, `LLAMA_STATIC_CRT`, and a CMake toolchain file setting `CMAKE_MSVC_RUNTIME_LIBRARY`, since CMake otherwise appends /MD). Without that, linking fails with LNK2005/LNK2038. After changing it, delete `src-tauri/target/debug/build/llama-cpp-sys-2-*`.
- Real-model tests are `#[ignore]`d: `FORGOR_MODELS=<dir with speech/ language/> FORGOR_RECORDING=<dir with mic.wav/system.wav> cargo test --release --lib real_models -- --ignored --nocapture`; `recorder::real_devices` records from the actual devices.
- Transcription choices are measured, not guessed (WER against human Dutch subtitles of podcasts/talk shows/interviews, clean and AAC-16 kbit "call" versions; the clips and tools lived in a scratch dir, not the repo). Segments ≥3 s are recognized alone; shorter ones get the preceding ~6 s of the same track as context and keep only their own words (`SHORT_SEGMENT`, `CONTEXT_SAMPLES`, `split_by_time`): 12.2% WER vs 13.5% (all alone) / 13.7% (all joined), 15.5% vs 19.0% / 18.5% on call audio. Joining long segments made Parakeet skip parts of sentences; alone, short Dutch replies came out English. Whisper turbo (forced nl) was no better and 6× slower; Qwen3-ASR 0.6B clearly worse; Core ML 3× slower than CPU for these int8 models.
- Echo: mic frames are cut out before recognition where the mic's loudness follows the system track (`echo_frames`, `cut_out`, threshold 0.6 swept on two real calls), then whole segments are still checked (`echo_correlation`, `is_echo`). The recorder fills gaps with silence by the clock (`gap_to_fill`): macOS delivers no system audio at all while nothing plays.
- Summary prompt has Samenvatting / Belangrijkste punten / Besluiten / Actiepunten; scored with fact checklists (`summary_eval` test). The Google/Unsloth QAT variants of Gemma 4 E4B scored the same as the current Q4_0. Meetings over ~24k tokens (~2 h) are summarized in parts; that path keeps decisions but can drop some action items.
- `FORGOR_DEBUG_TIME=1` / `FORGOR_DEBUG_ECHO=1` print processing stage times / per-segment echo scores.
- Speaker separation (optional model "speakers": pyannote segmentation + CAM++) runs on the system track (on the mic when the system track has no speech, i.e. in person); VAD segments are cut at speaker changes (`split_at_speakers`). Clustering threshold 0.9 (the default 0.5 gave ~80 speakers on one standup).
- Voices: `voice_prints` → `ProcessResult.voices`; named voices live in `voice_samples` (schema v6, one row per meeting+speaker, averaged per name, `data/voices.ts`) and are matched before summarizing (`match_voices`, `RECOGNIZE` 0.6 / `SUGGEST` 0.5, calibrated on a real standup). The summary model sees "Opnemer"/"Deelnemer"/names, never "Ik"/"Anderen" (Dutch "ik" made it give the others' tasks to the user).
- The dev app keeps recording audio (`KEEP_AUDIO`) and also writes `*.raw.wav` at the device rate; "Transcribe again" exists only there.
- In dev (unbundled binary) macOS attributes mic permission to the terminal/editor; without it the mic track is silent (zeros, no error). `src-tauri/Info.plist` has the usage strings for the bundled app.

## AI chat
- Built-in plugin `chat` (`src/plugins/chat/`): the app finds, the model only reads. A small model can't search on its own, so `search.ts#findSources` picks the sources first: notes split into sections (`noteDocs`; a picked meeting section brings that meeting's Besluiten along), open todos, other plugins' `chat` items (Jira tickets, Bitbucket PRs). Ranking fuses word search (BM25, prefix matching) and search by meaning (vectors) by rank; the project is a top-level folder named in the question or the one most top matches by meaning are in; "do I have todos" gets the real list (max 15, filtered by "this week/today", `dueWindow`); "do I have any pr's" gets the open pull requests, and an empty list is said as none (`asksPullRequests`, otherwise meaning search hands it nearby notes and the model says it can't find any); "which project has the most notes" is a count of notes per top-level folder (`asksMostNotes`); tickets in that folder are not notes. "the last …" favours new notes. Measured before building on a test workspace with 150 distractor notes: word search alone found 25/31 expected sources and answered "which cloud provider" with the outdated Azure; with meaning 31/31 and 23/24 answers right (~10 s per answer on an M4, ~7 s to the first word). The eval harness: `src-tauri/src/chat_eval.rs` (`chat_eval`, `chat_speed`, `chat_embed`, `#[ignore]`d).
- Search model: `search` = EmbeddingGemma 300M Q8_0 (`models/embed.rs`, `search_embed`), documents as `title: … | text: …`, questions as `task: search result | query: …`. Index: table `chat_index` (schema v11, key → hash of the text + base64 float32 vector), kept up to date by `indexer.ts` (plugin `start`: at start, 5 s after notes/todos change, when the model arrives; only changed text is embedded again).
- Answer: `chat.rs` (`chat_run`/`chat_cancel`, Gemma's multi-turn format, streamed over a Channel). The prompt (`systemPrompt`, `questionTurn`) is Dutch; the answer language is stated per question (`languageOf`: the rule "answer in the question's language" alone gave Dutch answers to English questions). Sources are numbered [n]; the page turns them into links and chips (`citedSources`), the model never writes ids. Attached items go first, and the prompt says "dit"/"this" means those and to summarize the description instead of repeating the title (the "only mention the name" rule made "what is this about" echo the title). A follow-up that only points at that item ("what is the ticket about", "what does this talk about") keeps it, description included (`sticksToAttachment`); other questions search as usual. A question with no content words adds no other sources. Follow-ups send the last three exchanges' text (no sources) and search short ones together with the previous question. "And after that?" after a todo question stays on that ordered list (most important first) and keeps the previous answer's language (`asksNext`).
- Rules for what a question means (`search.ts`): a question gets special treatment (the real PR/ticket list, counts of notes or todos) only when it is *purely* about that: every content word is a list word, a noun of that kind or a project name (`onlyAbout`). A single shared word is not enough ("which PR fixes NZP-41", "which folder has the notes about hosting", "wanneer is de volgende meeting" all went wrong when it was). A short question inherits the previous one only when it reads like a follow-up (`FOLLOW_UP`, `FOLLOW_UP_WORDS`, or under 2 content words). The model counts what it sees, so anything it might be asked to count is counted in code (`todoCounts`, `noteCounts`) or comes with the real total (`listTotal` when over `LIST_CAP`, and the prompt must say "geef de lijst én zeg dat het de eerste 15 van N zijn": a total phrased as the only instruction replaced the list). "No PR plugin" is `listMissing` (`itemKinds`), never "you have none". A key typed in the question (`namedItems`, "what is NZP-41 about") is treated as attached, so it gets its description. Attached text is capped (`capAttached`), history drops old `[n]` (`historyTurns`), questions are cut at `MAX_QUESTION`.
- Checked with the real model (scenario list in the session that added these: greetings, injection text inside a note, counting, list of 21, PRs off/none, named ticket, follow-ups): small Gemma follows the *last* instruction in the user turn, ignores "PIRATE"-style instructions inside notes (the system prompt also says so), and cites made-up "[heading]" or "[1]" when a counts block looks like a source (`NO_CITES`). Run scenarios with `chat_eval::chat_eval` (the filter `chat_eval` also runs the other two ignored tests, which panic without their env vars); `FORGOR_PROMPTS` lines may carry `turns` (a conversation) instead of `user`.
- One conversation, in plugin storage (`plugin:chat:conversation`); "New chat" clears it. Plugins add items with `chat: { kind, items, }` (`PluginChatItem`: text kept short, `detail()` fetches the full description when attached); items come from cached queries. The browser build's models are fakes (`platform/chat.ts`).

## Writing tools
- Crepe's own AI feature (`Crepe.Feature.AI`, on when the writing plugin is enabled and the language model is there: `useEditorWriter` → NoteEditor's `writer`): the selection-toolbar prompt, streaming into the doc and the diff review are Milkdown's. We give it a provider (`platform/writing.ts` → Rust `writing.rs`, streamed over a Tauri `Channel`) and our own `buildContext` (`aiContext` in NoteEditor: Crepe's falls back to plain text, which dropped images that the reply then replaced). The top-bar button is `AskAIButton` → `NoteEditorHandle.runAI` (focus first, then `AllSelection`: focusing re-reads the DOM selection, which can't span an image).
- Call Crepe AI commands by name (`"RunAI"`): importing `runAICmd` from `@milkdown/crepe/feature/ai` gives a second module copy whose key the editor doesn't know. `@milkdown/kit/plugin/{streaming,diff}` imports are the same copy Crepe uses.
- While streaming or reviewing, `markdownUpdated` doesn't save and markers aren't assigned. The review is one decision (per-change buttons hidden in editor.css: accepting one of many small changes left the review open, which blocks typing); `reviewKeys` adds Esc = reject and pulses the bar on typing. `onBeforeAI` saves and forces a version snapshot first.
- `writing.rs`: images, links, inline code and code blocks become placeholders `⟦n⟧` before the model sees the text (`protect`), are put back while streaming (`Restorer`; what stood on its own line gets its own line back, or an image block became an inline image without resize handle) and `check` warns when the reply loses or repeats one, or a `^t-` marker. The selection's language is stated in the prompt (a Dutch note or instruction turned English text Dutch), except when the instruction asks for a language (`asks_for_language`; with the rule, "vertaal naar het Nederlands" stopped translating). Empty todo lines in a reply are dropped (`EmptyTodos`); an empty reply fails, so Crepe puts the text back.
- The language model is shared and stays loaded 5 min after use (`models::llm`); it must be unloaded before exit (`RunEvent::Exit`) or llama.cpp's Metal code aborts, and before deleting its file (Windows).
- Real-model checks: `writing_eval` (a few cases, prints output/timing) and `writing_stress` (notes × prompts with automatic checks, `FORGOR_REPORT=<file.md>`). Letter-level tasks ("after every word ending in s") are beyond this model.

## Jira
- Jira Cloud only, email + API token (Basic auth); the user chose this over OAuth (no app registration or admin approval). The token is in the OS keychain (`keyring` crate, `src-tauri/src/jira.rs`), never in SQLite/settings; `settings.jiraAccount` holds site/email/name. The token is read from the keychain once per run and cached in memory, one read at a time (reading per request made macOS prompt over and over; "Always allow" is tied to the exact build, so the dev app asks again after each rebuild). All requests go through Rust (`jira_get`, read-only GET on `/rest/…`): the webview can't call Atlassian (CORS).
- `platform/jira.ts` (Tauri + a fake site for the browser build/e2e that answers the same paths), `lib/jira.ts` (types, `toIssue`, JQL/paths, sort/filter), `plugins/jira/state.ts` (TanStack hooks), `plugins/jira/*`. Jira queries are keyed `["jira", …]` and excluded (the plugin's `remoteQueries`) from the refresh-everything-on-local-change rule in `app/queries.ts` (otherwise every autosave hit Jira); they refresh after 1 min, on focus and every 5 min.
- Search uses `/rest/api/3/search/jql` (the old `/search` is gone) with `nextPageToken`; a folder's board uses `/rest/agile/1.0/board/{id}/issue`. Descriptions/comments are ADF, rendered by `JiraDoc` as React (never Jira's HTML); attachments need Jira's login, so they open in Jira.
- A folder's boards are `folders.jira_board` (schema v7, JSON list; 0.5.0 stored one object, `parseBoards` reads both). The folder merges my tickets from all of them (`useBoardsIssues`: a query per board, combined, deduplicated). The board picker is inline in the panel (a popover opened from a menu closed right away). Pages: `overview` (replaces the removed Calendar) and `folder` with the folder id as `param` (the folder's "View all"); the ticket panel is the plugin panel `issue` (`openIssue`; `fromFolder` gives it a back button). In the overview, tickets of a project whose board is linked to a folder with an icon show that icon (`useFolderForProject`). Tabs of removed pages are dropped on load (`REMOVED_PAGES` in store.ts).

## Bitbucket
- Bitbucket Cloud, read-only, built the same way as Jira: email + an Atlassian API token **with Bitbucket scopes** (`read:user/workspace/repository/pullrequest:bitbucket`; a Jira token doesn't work), kept in the keychain (`src-tauri/src/bitbucket.rs`, service "Forgor Bitbucket", cached per run), `settings.bitbucketAccount` holds email/name/uuid. All requests are GETs on `api.bitbucket.org/2.0/…` through Rust (`bitbucket_get`; paths checked by `valid_path`). `next` page links are full URLs: `nextPath` turns them back into paths.
- `platform/bitbucket.ts` (Tauri + a fake for the browser build/e2e that answers the same paths), `lib/bitbucket.ts` (types, `toPullRequest` from my point of view: `role` mine/review, reviewers from `reviewers` + `participants`; `jiraKeys`, `plainDescription`), `plugins/bitbucket/*`. Queries are keyed `["bitbucket", …]` (the plugin's `remoteQueries`).
- Only open PRs I opened or review; review requests I already approved are left out of every list (`approvedByMe`). Per linked repo: `pullrequests?state=OPEN&q=author.uuid OR reviewers.uuid` (role = mine when I'm the author); the overview adds `/2.0/workspaces/{ws}/pullrequests/{my uuid}` per workspace (mine in every repo; the cross-workspace `/2.0/pullrequests/{user}` answers 404 now, and there's no such list for reviews, so review requests only come from linked repos). That extra list failing is a warning on the page, not an error. Linked repos are `folders.bitbucket_repos` (schema v9, JSON list of `BitbucketRepoRef`). A PR's folder (its icon): the folder its repo is linked to, else one whose Jira board is on the project of a ticket key in its title/branch (`useFolderForPullRequest`). The panel `pr` has param `workspace/slug/id`; ticket keys open the Jira plugin's `issue` panel when Jira is on and connected (by plugin id, no import). The row's Review tag opens the PR on bitbucket.org.
- Builds: `/pullrequests/{id}/statuses` per PR (rows too, cached like the lists), the latest run per build key (`toBuilds`), summed up failed > running > stopped > passed (`summarizeBuilds`). Sidebar counts (both plugins) use the pages' own query keys, so they add no requests. Connecting resets (not removes) the plugin's queries: removed ones left the already-mounted sidebar count empty.

## Updates / releases
- Updater: `tauri-plugin-updater` against `https://github.com/LLefu/Forgor/releases/latest/download/latest.json`; pubkey in `tauri.conf.json`. The private key lives at `~/.tauri/forgor.key` (never in the repo) and in the GitHub secret `TAURI_SIGNING_PRIVATE_KEY`.
- UI state is in `src/app/updates.ts` (background check 5s after start, then every 6h; installing always needs a user click). Tauri calls are in `src/platform/updates.ts`.
- CHANGELOG.md is the single source for the in-app version history, GitHub release notes and latest.json notes. Add entries under `## Unreleased`; `npm run release` renames it and refuses to run when it is empty.
- Release: `npm run release X.Y.Z` → tag → `.github/workflows/release.yml` (draft → build both OSes → publish).
- Local signed build: set `TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/forgor.key)"` (the `_PATH` variant is not picked up). To test updates locally, pass `--config` with a localhost endpoint + `dangerousInsecureTransportProtocol: true`. Never ship that build.
